## Boundaries: optimization vs post_training vs rl

These three are intertwined by nature — the field itself stopped being separable (e.g. RL's Razor deliberately connects all three). The folders are shelves, not an ontology: each topic gets **one canonical file**, and the other folders cross-link to it instead of duplicating.

Filing procedure — ask, in order:

1. **Would this note survive unchanged if the model weren't an LLM at all?** If it's about the update rule or training dynamics independent of stage and objective → `optimization/` (Muon, NTK, muP, forgetting-vs-optimizer, batch/LR scaling, scaling laws).
2. **Is it a recipe applied to a pretrained model — which data, which loss, which stages?** → `post_training/` (SFT, DPO/IPO, distillation incl. OPD/OPSD, reward modeling, CAI).
3. **Does the difficulty exist only because the training data is generated by the current policy?** → `rl/` (policy gradients, PPO/GRPO mechanics, advantage estimation, importance sampling, async/staleness, estimating divergences from rollouts).

For boundary-straddlers, ask "which lens is doing the work in *my* note?" and give it that home. Worked examples: OPD is an objective (→ post_training) that happens to run on-policy (cross-ref rl); the k1/k2/k3 KL estimators solve a sampling-time estimation problem (→ [rl/kl_divergence.md](rl/kl_divergence.md)), while KL *definitions* stay in [fundamentals/classical/02](../fundamentals/classical/02_probability_and_info_theory/notes.md); scaling laws are stage-agnostic training dynamics (→ optimization, until a `pretraining/` section earns its existence).
